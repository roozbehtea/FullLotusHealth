# Insurance benefits check (Google Apps Script)

The form on `/insurance` posts to a web app URL. The Stedi key never goes in the website. It stays in Script Properties on the Apps Script project that already runs the scheduler.

The page reads one constant:

`var APPS_SCRIPT_URL` at the top of `assets/insurance-check.js`

Leave it as empty quotes until the steps below are done. An empty constant makes the form say to email the clinic instead of calling Stedi.

## 1. Add the file

1. Open [script.google.com](https://script.google.com) and open the Full Lotus project that already runs tea sits and booking (the web app URL in `_src/config.json` as `teasits_url`).
2. Add a script file named `insurance-check` and paste in all of `apps-script/insurance-check.gs`. Save.
3. This project already has `doPost` in `Code.gs`. Apps Script allows only one `doPost`. Delete `doGet` and `doPost` from the bottom of the new file (keep `insCheck_` and everything it calls). In `Code.gs`, inside the existing `doPost`, before the other actions, add:

```javascript
if (body.action === 'insurance_check') return json_(insCheck_(body));
```

If this project already has a function that calls Stedi, use that inside `insStedi_()` instead of the request in this file. Keep the sheet row and return only `active`, `inactive`, or `unknown`.

## 2. Set Script Properties

Project Settings → Script properties → Add script property:

| Property | Value |
| --- | --- |
| `STEDI_API_KEY` | The Stedi key already stored for this project, if the name differs, copy that value. Do not put the key in git or in `assets/insurance-check.js`. |
| `PROVIDER_NPI` | The clinic NPI, 10 digits. |
| `LEADS_SHEET_ID` | The spreadsheet id from its URL: `https://docs.google.com/spreadsheets/d/<this part>/edit`. The script adds a tab named `Insurance Leads`. |
| `NOTIFY_EMAIL` | Optional. Where to email a short notice. Leave it unset to skip the email. The message does not include the member ID or date of birth. |

`STEDI_API_KEY` is sent as the `Authorization` header with no `Key ` prefix, which is what Stedi's eligibility docs show. If an existing function in this project already uses a different header, keep using that function.

## 3. Deploy

1. Deploy → Manage deployments → pencil on the live web app → Version: New version → Deploy.
2. Execute as: Me. Who has access: Anyone.
3. Do not create a new deployment. A new URL would break booking and tea sits.
4. Copy the web app URL (it ends in `/exec`). It is the same URL the site already uses for booking.

## 4. Put the URL in the website

1. Open `assets/insurance-check.js`.
2. Set `var APPS_SCRIPT_URL = "";` to that URL, inside the quotes.
3. Run `python3 _src/build.py` only if you also changed `_src/build.py`. The constant is not generated by the build, so committing `assets/insurance-check.js` is enough.
4. Commit and push.

After later edits to `insurance-check.gs`, deploy a new version of the same web app so the URL does not change.

## What the check does

- Aetna PPO: asks Stedi whether the plan is active (service type `30`, Health Benefit Plan Coverage). Aetna's payer id in the file is `60054`.
- Other PPO: saves the row and does not call Stedi.
- The browser only receives `{status:"active"}`, `{status:"inactive"}`, or `{status:"unknown"}`. Benefit amounts are not stored and are not sent back.
- The sheet columns are timestamp, first name, last name, date of birth, email, phone, carrier, member ID, and a short result.
- A hidden company field is ignored, and those submissions are not saved.
